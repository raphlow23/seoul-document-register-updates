# 서울센터 공문 업무 v2.2.0

Windows 10/11 x64 프로그램입니다. 다운로드한 PDF·HWP·HWPX·ZIP을 확인하고 공유폴더 저장, Google 시트 수신·발신·직인대장 등록을 단계별로 진행합니다.

## 화면과 사용 순서

상단 메뉴는 **수신 접수 / 발신 작성 / 처리 이력**입니다. Google 연결과 업데이트는 **설정 · 연결**에 있습니다.

### 수신 접수

1. 같은 메일에서 받은 본 공문과 붙임을 함께 선택합니다. ZIP 내부 문서도 제목 출처로 선택할 수 있습니다.
2. 제목을 가져올 파일을 고릅니다. PDF 미리보기와 추천 제목을 보거나 필요한 영역을 드래그해 OCR하고 최종 제목을 수정합니다. 공문 기관·수신 종류·담당자·접수일을 확인합니다.
3. 저장할 위치를 여러 곳 체크합니다. 기존 폴더 이름 예시와 새 폴더 미리보기를 확인합니다. 공문·센터발송·회신 하위폴더는 원하는 항목만 만들고 번호는 1부터 연속으로 붙입니다.
4. ‘저장하고 수신 접수’를 누릅니다. 완료 화면의 큰 접수번호를 인쇄물에 직접 적습니다. 발신이 필요하면 ‘이 공문으로 발신 작성’으로 이어갑니다.

**폴더 순번과 구글 시트 접수번호는 별개**입니다. 각 저장 위치의 기존 폴더 순번을 따릅니다. 원본 다운로드와 기존 파일은 덮어쓰지 않습니다.

목록 삭제는 선택한 항목을 목록에서 숨깁니다. 파일·등록 이력을 삭제하지 않습니다. 다운로드에서 삭제·이동된 파일은 접수 대기 목록에서 빠지지만 등록 이력은 남습니다. 숨긴 파일은 ‘파일 추가’로 다시 표시할 수 있습니다.

### 발신 작성

1. 수신 접수가 완료된 문서를 선택합니다. 처리 이력에서도 발신 작성을 시작할 수 있습니다.
2. 일반 기초센터 발신 / 중앙 회신 / 시청 회신 / 업무연락 / 처리지침 / 시청 건축협의 회신 중 양식을 고릅니다. 선택한 양식에 따라 발신대장과 직인 분류·기본 저장 폴더가 정해집니다.
3. 수신 제목을 가져온 발신 제목, 수신 기관, 오늘 날짜, 기본 담당자를 확인합니다. 제목과 저장 위치는 수정할 수 있습니다. 직인 신청부서는 ‘편의증진부’, 신청자는 담당자, 날인자는 공란입니다. ‘직인 신청정보 · 발신 방법’에서 변경합니다. ‘작성 정보 저장’은 대장 등록 없이 작성 정보만 저장합니다.
4. ‘발신번호 받고 한글로 열기’를 누르면 대장에서 실제 번호를 받고, 번호와 당일 날짜를 넣은 양식 사본을 한글에서 엽니다. 수신 접수는 반복하지 않습니다. 본문은 OCR 또는 다른 한글에서 복사한 문구를 직접 붙여넣고 저장합니다. 메일 전송과 실제 직인 날인은 사용자가 합니다.

발신 파일명은 해당 양식의 접두어·실제 발신번호·현재 날짜·제목·뒤 표시를 따릅니다. 번호를 예측하거나 샘플 번호를 재사용하지 않습니다. 이미 저장된 같은 이름의 파일은 덮어쓰지 않습니다.

## 사용 중 양식 추가

설정 또는 발신 양식 선택 화면의 **양식 추가**에서 원본 .hwp를 등록합니다. 양식 이름·공문 종류·기본 저장 폴더와 시행번호·시행일의 현재 문구를 지정합니다. 번호와 날짜는 가능한 위치를 자동 제안하며 문서에서 문구를 선택해 바꿀 수 있습니다. 지정 문구는 문서에 한 번만 있어야 합니다.

번호·날짜 자리가 완전히 비어 있다면 원본 한글에서 `{{발신번호}}`, `{{발신일}}`을 넣어 저장한 양식을 추가합니다. 제목·수신처·담당자 자동 입력이 필요하면 `{{제목}}`, `{{수신처}}`, `{{담당자}}` 위치도 지정합니다. 지정하지 않은 항목은 한글에서 직접 입력합니다. 본문은 자동으로 채우지 않습니다.

양식 파일명에 `012. 26.11.02. 제목(센터-발송).hwp` 같은 형식이 있으면 접두어·번호 뒤 공백·발송/제출 뒤 표시를 제안합니다. 사용자 양식의 시행번호는 같은 발신번호로, 시행일은 `(26. 11. 2)`처럼 당일 날짜로 넣습니다. 양식은 이 PC의 개인 데이터 폴더에 복사하며 원본을 바꾸거나 공개 GitHub에 올리지 않습니다. 추가 개수에 맞춰 선택 목록을 스크롤할 수 있습니다.

선택한 양식이 없거나 번호·날짜의 자동 입력 위치가 달라졌으면 대장 등록 전에 중단합니다. 한 번 작성한 HWP를 다시 열 때는 기존 파일을 열며 새 발신번호를 받거나 본문을 덮어쓰지 않습니다.

## 원본 HWP와 OCR

원본 6종 HWP는 비공개 초기 설치본 또는 개인 양식 보충 ZIP으로 사용자 PC에 한 번 설치합니다. **공개 GitHub 설치·업데이트 파일에는 공문 원본과 업무 설정이 없습니다.** 업데이트는 기존 양식과 설정을 유지합니다.

HWP 저장에는 설치된 Windows 편집용 한컴 한글이 필요합니다. 원본 HWP를 한글 COM으로 열어 제목·수신처·담당자·시행번호·날짜 문구를 바꾸고 새 HWP로 저장합니다. 원본 본문과 문단을 유지하며 HWPX로 왕복 변환하지 않습니다. 저장 전후 스타일 정의·순서, 글꼴·글자 모양, 문단 스타일·들여쓰기·줄간격·번호·탭, 용지 서식을 비교하고 달라지면 내보내지 않습니다. 실제 본문은 한글의 기존 문단에서 수정하세요. 개발 PC에는 한글이 없어 실제 COM 저장과 화면 배치의 최종 확인은 업무용 PC에서 필요합니다.

스캔 PDF는 내장 PDFium과 Tesseract 한국어·영문 모델로 PC 안에서 읽습니다. 원본 문서를 외부 OCR 서버로 보내지 않습니다. 제목 후보와 인식된 지번·숫자는 원본과 대조합니다.

‘OCR 본문 추출 · 띄어쓰기 정리’는 기본적으로 2항부터 붙임 마지막 ‘끝.’까지 가져옵니다. 범위와 결과를 직접 수정하고 복사해 한글에 붙여 넣을 수 있습니다. Kiwi 모델은 공백만 정리하며 글자·숫자·문장부호 보존을 확인합니다. HE/Eo 등 잘못 읽힌 글자는 표시하고 사용자가 수정합니다. OCR 문장을 원본 HWP 문단에 자동으로 덮어쓰지 않습니다.

ZIP은 하위폴더와 최대 3단계 중첩 ZIP, 일반적인 UTF-8/CP949 파일명을 지원합니다. 첨부는 로컬 archive-cache에 보관합니다. 경로 이탈·링크·암호·손상·용량 초과는 중단합니다. 제한은 원본 200MB, 파일당 100MB, 해제 전체 500MB, 항목 1,000개입니다. ZIP 안의 파일을 실행하지 않습니다. 서로 다른 공문이 한 ZIP에 있으면 직접 풀어 공문별로 추가합니다.

## Google 연결

설정의 기본 방식은 browser입니다. ‘Google 로그인’으로 여는 일반 Edge/Chrome 창에서 편집 권한이 있는 계정으로 로그인해 시트를 확인합니다. 그 전용 브라우저 창을 모두 닫고 ‘연결 확인’을 누릅니다. Cloud 프로젝트·API 활성화·JSON은 필요 없습니다. 프로그램은 비밀번호를 입력받거나 추출하지 않습니다.

제어 연결 후 정확한 탭 이름과 선택 상태를 확인하고 시트 범위를 읽고 씁니다. 등록 중 전용 시트 창과 클립보드는 다른 작업에 사용하지 마세요. 기존 서식이 준비된 행을 사용합니다. 화면 구조·로그인 상태·권한이 바뀌면 중단해 안내합니다.

고급 설정의 oauth·service 방식은 별도 API 설정이 있을 때만 사용합니다. OAuth 토큰은 Windows DPAPI로 현재 사용자에 암호화합니다.

수신·발신·직인 단계마다 로컬 이력과 등록 표시를 기록합니다. 실패 후 완료된 단계를 반복하지 않으며 결과가 불확실하거나 다른 값이 들어오면 확인을 요청합니다. 공유폴더 잠금이 다른 사람의 시트 수동 편집까지 막지는 않습니다.

## 설치와 자동 업데이트

설치 ZIP 전체 압축을 풀고 기존 프로그램을 종료한 뒤 install.cmd를 실행합니다. 이전 버전 삭제는 필요 없습니다. 최초 업무 경로·시트 ID·원본 양식은 별도로 설정합니다.

실행할 때 GitHub Releases의 서명된 latest.json을 확인하고 새 실행파일을 내려받아 교체·재시작합니다. 실행 중에는 1시간마다 확인하고 처리·편집 중에는 적용을 미룹니다. Ed25519 서명·SHA-256·숫자 버전을 검증하며 새 실행파일 점검 실패 시 이전 파일을 복구합니다. GitHub 로그인은 필요 없습니다.

설정·SQLite 이력·양식·연결 정보는 `%LOCALAPPDATA%\SeoulDocumentRegister`에 보관하며 업데이트에 유지됩니다. 공개 배포 파일에 사용자 설정·공유 경로·시트 ID·인증 정보·서명 개인키를 넣지 않습니다.

## 개발과 검증

- Python 3.12 x64, requirements.txt로 의존성을 설치합니다.
- `python -m unittest discover -q`: 등록·중복 방지·OCR·압축·인증·업데이트·HWP 관련 검사.
- `python ui_smoke.py`: 기존 문서 선택·저장 위치·발신·OCR 대화창 검사.
- `python app.py --test-workflow`: 임시 로컬 파일과 모의 대장으로 실제 단계 화면·작업 스레드·첨부 묶기·별도 폴더 순번·실패 재시도·발신/직인 등록·이력·설정을 검사합니다. 실제 업무 시트나 공유폴더에 쓰지 않습니다.
- `python app.py --self-test`: UI·의존성·한국어 OCR·TLS 인증서 확인.
- CI는 공식 Python으로 PyInstaller 실행파일을 빌드하고 위 단계 화면 검사를 배포 실행파일로 다시 수행합니다. Ed25519 서명은 관리 PC에서만 하고 검증한 매니페스트로 공개 설치 ZIP을 게시합니다.
- OCR 런타임은 conda-forge Tesseract 5.5.1과 LGPL libarchive 3.8.11을 사용합니다. 공개 한국어 모델, 라이선스·빌드 정보·대응 소스를 함께 배포합니다. 공문 원본은 별도로 보관합니다.
