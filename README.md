## v2.8.6

제목 확인 화면의 최종 제목을 위쪽 2~3줄 입력칸으로 배치하고 추천 제목을 첨부파일 줄의 선택 메뉴로 옮겼습니다. OCR 본문은 나머지 높이를 사용하고 세로 스크롤을 지원합니다. `본문 크게`에서 전체 본문을 넓게 읽고 선택 문장을 제목으로 넣거나 복사할 수 있습니다. 왼쪽 원문 미리보기와 기존 등록 동작은 유지합니다.

## v2.8.5

다운로드 자동 확인은 실행할 때 기본으로 켜집니다. 감시 시작 전에 다른 시작 작업이 실행되어 체크가 꺼지던 순서 문제를 수정했습니다. 실행 중에는 직접 끌 수 있습니다. 목록에서 삭제한 파일을 다시 다운로드하거나 수동 추가하면 이전 접수번호·저장 경로·발신 진행을 이어받지 않는 새 처리 건으로 검토합니다. 이전 시트 행과 저장 파일은 건드리지 않고 로컬 이전 기록도 보관합니다. 삭제만 한 기존 파일이 즉시 다시 표시되지는 않습니다.

메일의 함께 다운로드 ZIP은 안의 PDF를 우선 선택해 OCR과 미리보기를 표시합니다. 잘못된 HWPX나 읽지 못하는 첨부가 있어도 제목 확인 화면에서 다른 첨부를 선택하거나 제목을 직접 입력할 수 있습니다. PDF·한글 확장자가 실제 내용과 다른 경우도 파일 내용을 확인해 읽습니다. ZIP 원본과 다른 첨부는 함께 보관합니다.

## v2.8.4

`발신 작성 → ＋ 새 발신 작성`으로 수신 문서 없이 공문을 새로 작성할 수 있습니다. HWP 양식 선택 후 발신 제목·수신 기관·저장 위치를 지정하고 발신번호를 받으면 양식 사본을 한글에서 엽니다. 발신대장과 직인날인대장에만 등록하며 수신대장 등록이나 수신번호 생성은 하지 않습니다. 초안은 발신 목록에서 다시 열고 초기화·목록 삭제할 수 있습니다. 기존 수신 공문에서 이어서 발신하는 방법도 유지됩니다.

## v2.8.3

실행 파일과 OCR 등 구성 파일 다운로드도 GitHub HTTP 오류나 연결 끊김이 있으면 다른 다운로드 경로와 GitHub 공식 배포 API를 통해 재시도합니다. API에서 확인한 버전·파일명·크기·해시도 서명된 안내와 비교합니다. 중단된 부분 파일의 내용은 초기화하고 서명에 포함된 크기·해시를 확인한 파일만 적용합니다. 업데이트 안내의 다른 GitHub 경로 사용, 긴 한글 경로 수정과 자동 재실행을 함께 포함합니다.

## v2.8.2

GitHub 릴리스의 업데이트 안내 다운로드가 HTTP 504나 연결 오류로 실패하면 같은 저장소의 다른 GitHub 경로에서 서명된 안내를 읽습니다. 서명과 실행 파일의 크기·해시 검증은 유지하며 사용자 지정 업데이트 경로는 임의로 다른 저장소로 전환하지 않습니다. 긴 한글 제목의 보관 폴더 이전 오류 수정도 포함합니다. 업데이트를 받지 못한 구버전은 설치 ZIP 전체 압축을 풀고 기존 프로그램을 종료한 뒤 `install.cmd`를 한 번 실행하세요. 기존 설정·이력·사용자 양식은 유지됩니다.

## v2.8.1

긴 한글 공문 제목을 포함한 되돌리기 보관 자료를 설치 폴더로 이전할 때 발생하던 `WinError 3` 오류를 수정했습니다. Windows의 확장 경로를 사용해 400자 이상의 경로에서도 복사·검증·정리를 수행하며 화면과 기록의 경로 표시는 유지합니다. 중단된 이전 작업은 기존 기록에서 재시도하고, 복사 검증과 기록 갱신을 마친 뒤 원본을 정리합니다. 설정의 `이전 공유폴더 · 임시자료 정리`에서 다시 실행할 수 있습니다.

## v2.8.0

되돌리기 파일과 브라우저 등록 임시 이력은 설치된 EXE 옆 `임시보관` 폴더에 저장합니다. PyInstaller의 압축 해제 폴더나 공유 실적 폴더에 만들지 않습니다. 브라우저 입력이 확인되면 임시 JSON을 지우고 중복 등록 확인에 필요한 최소 정보만 설치 폴더의 `수발신-등록확인.sqlite`에 보관합니다. 다시 저장이 끝난 되돌리기 보관 파일도 실제 사용 중인 원본 참조가 없고 변경되지 않았을 때 정리합니다.

프로그램 시작 후 기존 공유폴더의 `.수발신-되돌리기`와 `.수발신-브라우저이력`을 설치 폴더로 이전합니다. 파일 내용과 구성을 검증하고 로컬 등록 기록의 경로를 먼저 갱신한 뒤 공유폴더의 기존 자료를 제거합니다. 복사 실패·중단·변경 파일이 있으면 원본을 보호합니다. 미완료 등록·재저장 대기·마지막 첨부 사본은 남겨 두며, 설정의 `이전 공유폴더 · 임시자료 정리`로 재시도할 수 있습니다.

## v2.7.9

작업표시줄에서 아이콘이 작게 보이던 여백을 줄였습니다. 기존 파란 문서·흰 선·민트색 및 파란색 화살표는 유지하고 각 Windows 아이콘 크기의 캔버스를 실제 그림으로 채웁니다. 작은 크기에서 그림의 너비가 16픽셀은 12→16, 24픽셀은 18→24, 32픽셀은 24→32로 커집니다. 새 아이콘 해시로 보관 파일과 이 프로그램의 바로가기도 갱신합니다.

메인 화면의 하단 상태 안내가 잘리지 않도록 내용 영역보다 먼저 필요한 높이를 확보합니다. 안내 및 업데이트 문구는 창 너비에 맞춰 줄바꿈되며 아래쪽 여유 공간을 유지합니다.

발신 작성 목록에 `발신 초기화 · 다시 시작`과 `목록에서 삭제`를 추가했습니다. 두 동작 모두 이전 발신·직인 등록 진행과 번호를 새 작성에 재사용하지 않으며 수신 접수·구글시트 기존 행·저장 파일은 유지합니다. 다시 시작은 새 등록 식별자로 양식 선택부터 진행하고 등록할 때 최신 대장을 읽어 새 번호를 받습니다. 목록 삭제 후에는 처리 이력에서 해당 수신 문서를 골라 다시 발신을 시작할 수 있습니다.

설정의 `양식 관리 · 저장 위치`에 완화공문을 추가했습니다. 완화공문은 일반 공문 유형이며 기본 저장 위치는 `3.완화신청`입니다. `HWP 연결`로 원본 양식을 지정하고 번호·날짜 입력 위치를 확인합니다. 기본 양식과 사용자 양식의 표시 이름 변경·목록 삭제를 지원하며 삭제한 양식의 원본 파일과 기존 공문 연결 정보는 보존합니다. 삭제 항목은 업데이트 뒤 자동으로 되살리지 않습니다.

## v2.7.8

작업표시줄 아이콘 연결을 수정했습니다. 실행 중인 창에 작은/큰 아이콘을 명시하고 Windows 앱 식별자·다시 실행 아이콘·실행 명령을 연결합니다. 아이콘 파일은 종료하면 사라지는 임시 폴더 대신 사용자 프로그램 자료 폴더에 보관합니다. 이 프로그램을 실행하는 기존 바탕화면·시작 메뉴·고정 바로가기만 갱신하며 다른 앱과 기존 실행 인자는 바꾸지 않습니다. 고정 추가/해제나 탐색기 재시작을 강제로 수행하지 않습니다.

설정 창의 업데이트 확인·설정 저장·닫기 버튼은 하단에 항상 표시합니다. 기본·고급 설정은 스크롤할 수 있고 창 크기에 맞춰 설명 문장이 줄바꿈됩니다. 기존 설정 값은 그대로 유지합니다.

## v2.7.7

OCR의 libcurl.dll 누락을 수정했습니다. 일반·지연 DLL 의존성을 재귀 확인하고 필수 DLL이 없으면 빌드를 중단합니다. 개발 PC의 설치 프로그램에 기대지 않도록 OCR 자식 프로세스의 DLL 검색 경로와 PATH를 분리하여 검증합니다. Windows 시스템 오류창 때문에 OCR이 멈추는 대신 프로그램에서 오류를 안내합니다. 새 OCR 구성은 최초 한 번 교체·설치합니다.

제목 확인 화면에서 완화공문을 선택하면 `완화된 세부기준의 승인신청에 따른 의견 요청(주소)`를 즉시 기본 입력하고 수신 종류를 공문으로 맞춥니다. 선택 파일명에서 주소를 우선 추출하고, `완화승인신청서` 같은 서식 이름은 주소로 사용하지 않습니다. 주소를 찾지 못하면 직접 입력하도록 안내합니다. 직접 수정한 제목은 늦게 도착하는 OCR 결과로 덮어쓰지 않습니다. 폴더 제목의 구청명·날짜·순번 형식은 유지합니다.

실행 파일·프로그램 창·설치 바로가기에 사용자가 선택한 투명 아이콘을 적용했습니다. 파란 문서와 흰색 선·테두리, 민트색 수신 화살표·파란색 발신 화살표를 사용합니다.

## v2.7.6

전체 화면에 밝은 카드 구성과 둥근 버튼·입력칸·체크박스·선택 표시를 적용했습니다. 저장 위치는 큰 체크 아이콘으로 선택하며 최종 폴더 미리보기를 항상 표시합니다. 길어진 설정은 스크롤해서 확인할 수 있습니다. 기존 키보드 선택·드래그 첨부·접수·발신·되돌리기 기능을 유지합니다.

OCR 엔진과 언어 자료는 별도 구성 파일로 최초 한 번 설치하고 재사용합니다. 실행할 때마다 이 자료를 임시 폴더에 풀지 않습니다. 새 설치본은 install.cmd에서 미리 설치하며, 기존 버전의 자동 업데이트 후에는 창을 연 다음 백그라운드에서 한 번 준비합니다. OCR이 필요한 작업은 준비가 끝나면 이어집니다. 설치된 파일은 프로그램에 포함된 해시와 대조하고, 파일이 없거나 손상되면 다시 준비합니다. 설정·접수 이력·한글 양식은 보존합니다.

공문 기관 목록과 저장 위치 화면에 ‘완화공문’을 별도로 추가합니다. 수신대장은 일반 ‘공문’, 저장 위치는 ‘3.완화신청’, 기본 내부 폴더는 ‘1.완화신청자료’입니다. 서울시청 공문의 새 접수에서는 완화신청을 분리하고, 이미 저장·등록을 시작한 구버전 건은 기존 위치로 복구할 수 있습니다. 구청명·주소·수신접수 제목과 폴더 이름은 확인·수정할 수 있습니다.

## v2.7.5

`3.완화신청`을 체크하고 위치 이름을 누르면 구청명(예: 강남구청), 주소·사업명, 수신접수 제목을 확인·수정할 수 있습니다. 수신접수 기본 제목은 `완화된 세부기준의 승인신청에 따른 의견요청 (주소·사업명)`이고, 폴더 기본 이름은 `001.26.11.05._[강남구청] 완화된 세부기준의 승인신청에 따른 의견요청(주소·사업명)`입니다. 실제 폴더 연번은 해당 저장 위치의 다음 순번을 사용하고 날짜는 접수일을 사용합니다. 공문에 적힌 주소·사업명과 `외1` 같은 추가 표기는 보존합니다. 폴더 제목은 따로 수정할 수 있으며 구청명은 시트 제목에 붙이지 않습니다. 이미 파일 저장이나 시트 등록을 시작한 건은 기존 제목과 위치를 유지합니다.

## v2.7.3

저장 위치를 여러 개 체크한 뒤 위치 이름을 선택하면 그 위치의 폴더 제목과 내부 폴더 생성 여부를 각각 설정합니다. ‘이 위치에 내부 폴더 만들기’를 해제하면 공문 폴더 바로 아래에 첨부를 저장합니다. 중앙지침·보건복지부지침에서 ‘연도 폴더에 수신 파일만 저장’을 선택하면 2026 또는 2026년 등의 연도 폴더에 파일만 저장하고 제목별 공문 폴더와 내부 폴더는 만들지 않습니다. 기존 연도 폴더와 기존 파일은 유지합니다. 각 위치의 실제 생성 예정 이름은 아래 미리보기에서 확인할 수 있으며 대장 제목은 바뀌지 않습니다.

처리지침·업무연락 수신대장의 번호 머리글을 인식하고 머리글 행이 이동한 경우에도 확인합니다. 입력 열 구성이 다르거나 머리글이 여러 개면 등록 전에 중단합니다. 이미 저장된 건은 기존 위치에서 수신 등록을 다시 시도하며 새 접수번호를 중복 생성하지 않습니다.

# 서울센터 공문 업무 v2.5.1

Windows 10/11 x64 프로그램입니다. PDF·한글·엑셀·HTML·워드·도면·ZIP 첨부파일을 모아 공유폴더 저장, Google 시트 수신·발신·직인대장 등록을 단계별로 진행합니다.

## 화면과 사용 순서

상단 메뉴는 **수신 접수 / 발신 작성 / 처리 이력**입니다. Google 연결과 업데이트는 **설정 · 연결**에 있습니다.

**← 이전 단계 (파일 취소)**는 해당 단계에서 프로그램이 저장한 파일·폴더를 원래 위치에서 제거하고 이전 화면으로 돌아갑니다. 수신에서 돌아가면 그 공문의 수신·발신 저장 파일을, 발신에서 돌아가면 발신 저장 파일만 취소합니다. **구글시트 수신·발신·직인대장과 기존 번호·등록 이력은 유지합니다.** 되돌린 문서를 다시 진행하면 기존 접수번호로 파일만 저장하며 대장을 다시 등록하지 않습니다. 이미 등록한 제목·기관·날짜는 유지하고 폴더 제목·저장 위치·추가 첨부파일을 정합니다.

파일은 복구할 수 있도록 공유폴더의 `.수발신-되돌리기` 보관 위치로 옮깁니다. 처리 이력의 본문·저장 결과에서 보관 위치를 확인할 수 있습니다. 프로그램의 생성 표시와 파일 해시를 확인하고, 직접 추가·수정한 파일이나 다른 문서가 섞여 있으면 전체 취소 전에 중단해 보호합니다. 이전 버전 HWP처럼 생성 당시 해시가 없는 파일도 자동으로 제거하지 않습니다. 원본 다운로드와 등록한 HWP 양식은 유지합니다. **선택 내용 다시 확인**은 파일 취소 없이 내용을 확인하며, 연결 설정은 별도 **설정 · 연결**에서 엽니다.

### 수신 접수

1. 같은 메일에서 받은 본 공문과 붙임을 함께 선택합니다. ZIP 내부 문서도 제목 출처로 선택할 수 있습니다.
2. 제목을 가져올 파일을 고릅니다. PDF 미리보기와 추천 제목을 보거나 필요한 영역을 드래그해 OCR하고 최종 제목을 수정합니다. 공문 기관·수신 종류·담당자·접수일을 확인합니다.
3. 저장할 위치를 여러 곳 체크합니다. 기존 폴더 이름 예시와 새 폴더 미리보기를 확인합니다. 공문·센터발송·회신 하위폴더는 원하는 항목만 만들고 번호는 1부터 연속으로 붙입니다.
4. ‘저장하고 수신 접수’를 누릅니다. 완료 화면의 큰 접수번호를 인쇄물에 직접 적습니다. 발신이 필요하면 ‘이 공문으로 발신 작성’으로 이어갑니다.

**폴더 순번과 구글 시트 접수번호는 별개**입니다. 각 저장 위치의 기존 폴더 순번을 따릅니다. 원본 다운로드와 기존 파일은 덮어쓰지 않습니다.

목록 삭제는 선택한 항목을 목록에서 숨깁니다. 파일·등록 이력을 삭제하지 않습니다. 다운로드에서 삭제·이동된 파일은 접수 대기 목록에서 빠지지만 등록 이력은 남습니다. 숨긴 파일은 ‘파일 추가’로 다시 표시할 수 있습니다.

다운로드 자동 확인·드래그·파일 선택은 PDF·HWP/HWPX·엑셀·CSV·HTML·워드·프레젠테이션·텍스트·ZIP·DWG·DXF를 표시합니다. 이미지·실행파일·기타 형식, 다운로드 중 임시파일과 Office 잠금 파일은 제외합니다. ZIP 내부도 같은 기준으로 문서·도면을 모으며 원본 ZIP은 바꾸지 않습니다. 도면·HTML·엑셀은 내용 분석이나 실행 없이 첨부로 보관합니다. 자동 확인 전에 받은 파일은 ‘파일 추가’로 선택하세요.

제목·본문을 추출하는 형식은 PDF·HWP·HWPX이며 제목 선택창에서 우선 표시합니다. 엑셀 등 다른 파일은 내용을 분석하거나 실행하지 않고 첨부로 함께 저장합니다. 엑셀만 있어도 제목을 직접 입력하거나 파일명에서 선택해 진행할 수 있습니다.

빠진 첨부파일은 기존 공문을 선택한 뒤 **공문에 첨부 추가**에서 PDF·HWP·HWPX·ZIP을 고릅니다. 또는 목록에서 기존 공문 한 건과 새 첨부파일을 함께 선택해 다음으로 진행합니다. 이전 저장 파일이 남아 있으면 먼저 파일 저장만 취소하고 같은 공문에 첨부를 추가합니다. 구글시트 번호·제목은 유지합니다. 취소한 공문은 접수 대기 목록에도 표시하며, 다시 저장할 때 새 첨부까지 모두 복사합니다. 별도로 이미 접수한 다른 공문은 합치지 않습니다.

### 발신 작성

1. 수신 접수가 완료된 문서를 선택합니다. 처리 이력에서도 발신 작성을 시작할 수 있습니다.
2. 센터회신 / 센터발송 / 중앙회신 / 시청회신 / 업무연락 / 처리지침 / 건축허가&사업계획승인·사용승인&사용검사 중 양식을 고릅니다. 선택한 양식에 따라 발신대장과 직인 분류·기본 저장 폴더가 정해집니다.
3. 수신 제목을 가져온 발신 제목, 수신 기관, 오늘 날짜, 기본 담당자를 확인합니다. 제목과 저장 위치는 수정할 수 있습니다. 직인 신청부서는 ‘편의증진부’, 신청자는 담당자, 날인자는 공란입니다. ‘직인 신청정보 · 발신 방법’에서 변경합니다. ‘작성 정보 저장’은 대장 등록 없이 작성 정보만 저장합니다.
4. ‘발신번호 받고 한글로 열기’를 누르면 대장에서 실제 번호를 받고, 번호와 당일 날짜를 넣은 양식 사본을 한글에서 엽니다. 수신 접수는 반복하지 않습니다. 본문은 OCR 또는 다른 한글에서 복사한 문구를 직접 붙여넣고 저장합니다. 메일 전송과 실제 직인 날인은 사용자가 합니다.

발신 파일명은 해당 양식의 접두어·실제 발신번호·현재 날짜·제목·뒤 표시를 따릅니다. 번호를 예측하거나 샘플 번호를 재사용하지 않습니다. 이미 저장된 같은 이름의 파일은 덮어쓰지 않습니다.

## 수신·발신 공문폴더 이름과 내부 구성

수신·발신 저장 위치를 고르면 기존 폴더 이름을 읽어 번호·날짜·접두어 형식을 자동 적용합니다. 화면에는 `{date}{title}` 같은 표식 대신 `005. 26.11.03. 새 공문`처럼 실제 생성될 이름을 보여 줍니다. 기존 예시나 실제 이름 목록에서 다른 형식을 선택하거나 ‘직접 수정’으로 이름을 고칠 수 있습니다. 폴더 제목을 바꾸어도 구글 시트 제목과 HWP 제목은 바뀌지 않습니다.

저장 위치를 바꾸면 새 위치에 기존 폴더가 있는 경우 그곳의 형식을 우선 제안합니다. 새 위치가 비어 있으면 해당 저장 항목에서 이전에 쓰던 형식과 내부 구성을 이어 씁니다. 프로그램에서 아직 저장한 적이 없는 기존 폴더도 설정 변경 직전에 이름을 읽어 형식을 보관합니다. 저장 위치를 바꾸어도 켜 둔 다운로드 감시는 유지합니다. 번호 형식은 새 위치에서 1번부터 시작하고, 날짜 형식은 날짜로 시작하며 불필요한 번호를 붙이지 않습니다. 폴더 순번은 구글 시트 수신·발신번호와 무관합니다.

내부는 기관에 맞는 기초공문/중앙공문/시청공문, 센터발송, 기초회신/중앙회신/시청회신 중 고릅니다. 공문+회신만 고르면 1.시청공문 / 2.시청회신처럼 번호를 당깁니다. 발신 HWP를 어느 내부폴더에 넣을지도 선택합니다. 공문폴더 만들기를 해제하면 기존처럼 HWP만 바로 저장합니다. 저장 중 실패한 문서는 이미 계획한 폴더를 다시 사용하며 다른 기존 폴더와 파일을 덮어쓰지 않습니다.

수신번호와 발신번호는 각각 완료 화면과 처리 이력에서 확인합니다. 발신번호는 HWP 파일명 맨 앞과 양식 하단에 넣고, 폴더 이름은 저장 위치의 별도 형식으로 만듭니다.

## 사용 중 양식 추가

설정 또는 발신 양식 선택 화면의 **HWP 양식 넣기**를 누르고 원본 .hwp 파일을 바로 선택합니다. ZIP이나 별도 설치 명령은 필요 없습니다. 열린 등록 창에 HWP 하나를 끌어다 놓아도 됩니다. 원본의 번호·날짜·제목·수신처를 자동 제안하므로 내용을 확인하고 양식 이름·공문 종류·기본 저장 폴더를 정해 등록합니다. 등록 즉시 목록에 반영하며 재실행할 필요가 없습니다.

같은 번호·날짜 문구가 본문에도 있으면 오른쪽 목록의 주변 문장을 보고 바꿀 위치를 선택합니다. 위치를 고르지 않으면 등록하지 않습니다. 선택한 위치만 내부 사본에서 고유 표식으로 준비하며 원본, 타 기관 공문 번호·날짜, 스타일·문단·표·그림을 유지하는지 검증합니다. 이후 발신 공문을 만들 때 실제 발신번호와 당일 날짜로 그 위치만 바꿉니다. 반복된 문구는 한 문단 안의 연속된 글자여야 합니다.

번호·날짜 자리가 완전히 비어 있다면 원본 한글에서 `{{발신번호}}`, `{{발신일}}`을 넣어 저장한 양식을 추가합니다. 제목·수신처·담당자 자동 입력이 필요하면 `{{제목}}`, `{{수신처}}`, `{{담당자}}` 위치도 지정합니다. 지정하지 않은 항목은 한글에서 직접 입력합니다. 본문은 자동으로 채우지 않습니다.

양식 파일명에 `012. 26.11.02. 제목(센터-발송).hwp` 같은 형식이 있으면 접두어·번호 뒤 공백·발송/제출 뒤 표시를 제안합니다. 사용자 양식의 시행번호는 같은 발신번호로, 시행일은 `(26. 11. 2)`처럼 당일 날짜로 넣습니다. 양식은 이 PC의 개인 데이터 폴더에 복사하며 원본을 바꾸거나 공개 GitHub에 올리지 않습니다. 추가 개수에 맞춰 선택 목록을 스크롤할 수 있습니다.

선택한 양식이 없거나 번호·날짜의 자동 입력 위치가 달라졌으면 대장 등록 전에 중단합니다. 한 번 작성한 HWP를 다시 열 때는 기존 파일을 열며 새 발신번호를 받거나 본문을 덮어쓰지 않습니다.

## 원본 HWP와 OCR

기본 7종 또는 새로 만든 HWP는 프로그램의 **HWP 양식 넣기**에서 원본 파일을 직접 등록해 사용합니다. 별도 양식 ZIP 설치는 필요 없습니다. 이미 설치된 기본 양식과 직접 추가한 양식은 유지합니다. **공개 GitHub 설치·업데이트 파일에는 공문 원본과 업무 설정이 없습니다.** 업데이트는 기존 양식과 설정을 유지합니다. 본문의 타 기관 공문 번호와 날짜는 사용자가 직접 입력합니다.

HWP 저장에는 설치된 Windows 편집용 한컴 한글이 필요합니다. 원본 HWP를 한글 COM으로 열어 제목·수신처·담당자·시행번호·날짜 문구를 바꾸고 새 HWP로 저장합니다. 원본 본문과 문단을 유지하며 HWPX로 왕복 변환하지 않습니다. 저장 전후 스타일 정의·순서, 글꼴·글자 모양, 문단 스타일·들여쓰기·줄간격·번호·탭, 용지 서식을 비교하고 달라지면 내보내지 않습니다. 실제 본문은 한글의 기존 문단에서 수정하세요. 개발 PC에는 한글이 없어 실제 COM 저장과 화면 배치의 최종 확인은 업무용 PC에서 필요합니다.

스캔 PDF는 내장 PDFium과 Tesseract 한국어·영문 모델로 PC 안에서 읽습니다. 원본 문서를 외부 OCR 서버로 보내지 않습니다. 제목 후보와 인식된 지번·숫자는 원본과 대조합니다.

‘정리된 본문 확인 · 복사’를 열면 제목·1항·하단 시행 정보를 제외하고 2항부터 붙임 마지막 ‘끝.’까지 자동 추출하여 띄어쓰기를 정리합니다. 왼쪽에서 원본 PDF의 페이지를 확인하고, 오른쪽에서 정리된 본문을 수정·복사해 한글에 붙여 넣습니다. HWP/HWPX는 내장 첫 화면 미리보기를 표시하며 전체 인식 내용은 ‘OCR 원문·범위 수정’ 탭에서 확인합니다. 2항을 찾지 못하면 전체 문서를 임의로 가져오지 않고 직접 범위를 선택하도록 안내합니다. Kiwi 모델은 공백만 정리하며 글자·숫자·문장부호 보존을 확인합니다. HE/Eo 등 잘못 읽힌 글자는 표시하고 사용자가 수정합니다. 원본 파일과 한글 양식의 서식은 바꾸지 않습니다.

ZIP은 하위폴더와 최대 3단계 중첩 ZIP, 일반적인 UTF-8/CP949 파일명을 지원합니다. 첨부는 로컬 archive-cache에 보관합니다. 경로 이탈·링크·암호·손상·용량 초과는 중단합니다. 제한은 원본 200MB, 파일당 100MB, 해제 전체 500MB, 항목 1,000개입니다. ZIP 안의 파일을 실행하지 않습니다. 서로 다른 공문이 한 ZIP에 있으면 직접 풀어 공문별로 추가합니다.

## Google 연결

설정의 기본 방식은 browser입니다. ‘Google 로그인’으로 여는 일반 Edge/Chrome 창에서 편집 권한이 있는 계정으로 로그인해 시트를 확인합니다. 그 전용 브라우저 창을 모두 닫고 ‘연결 확인’을 누릅니다. Cloud 프로젝트·API 활성화·JSON은 필요 없습니다. 프로그램은 비밀번호를 입력받거나 추출하지 않습니다.

제어 연결 후 정확한 탭 이름과 선택 상태를 확인하고 시트 범위를 읽고 씁니다. 등록 중 전용 시트 창과 클립보드는 다른 작업에 사용하지 마세요. 기존 서식이 준비된 행을 사용합니다. 화면 구조·로그인 상태·권한이 바뀌면 중단해 안내합니다.

시트 맨 앞 숨김 행은 실제 선택 범위 주소를 기준으로 보정하여 대장 머리글이 다른 행으로 밀리지 않게 읽습니다. 복사 결과가 잠시 비어 있으면 기다렸다가 재시도합니다. 복사된 행·열 수나 입력할 셀 주소가 예상과 다르면 대장에 쓰지 않고 중단합니다. 숨김·필터·기존 서식은 바꾸지 않습니다.

고급 설정의 oauth·service 방식은 별도 API 설정이 있을 때만 사용합니다. OAuth 토큰은 Windows DPAPI로 현재 사용자에 암호화합니다.

수신·발신·직인 단계마다 로컬 이력과 등록 표시를 기록합니다. 실패 후 완료된 단계를 반복하지 않으며 결과가 불확실하거나 다른 값이 들어오면 확인을 요청합니다. 공유폴더 잠금이 다른 사람의 시트 수동 편집까지 막지는 않습니다.

## 설치와 자동 업데이트

첨부 목록은 원본 파일의 수정 날짜가 최신인 순서로 표시합니다. ZIP은 압축파일 자체의 수정 날짜, 여러 첨부를 묶은 공문은 첨부 중 가장 최근 수정 날짜를 사용합니다. 목록에 수정 날짜를 표시하며 파일을 수정하면 순서를 다시 반영합니다.

설치 ZIP 전체 압축을 풀고 기존 프로그램을 종료한 뒤 install.cmd를 실행합니다. 이전 버전 삭제는 필요 없습니다. 최초 업무 경로·시트 ID·원본 양식은 별도로 설정합니다.

실행할 때 GitHub Releases의 서명된 latest.json을 확인하고 새 실행파일을 내려받아 교체·재시작합니다. 업데이트 후에는 도우미와 별도 실행환경으로 새 창을 열고, 창 준비 응답을 받은 뒤 완료 기록을 남깁니다. 시작 직후 종료되면 최대 3회 재시도합니다. 실행 중에는 1시간마다 확인하고 처리·편집 중에는 적용을 미룹니다. Ed25519 서명·SHA-256·숫자 버전을 검증하며 새 실행파일 점검 실패 시 이전 파일을 복구합니다. GitHub 로그인은 필요 없습니다.

설정·SQLite 이력·양식·연결 정보는 `%LOCALAPPDATA%\SeoulDocumentRegister`에 보관하며 업데이트에 유지됩니다. 공개 배포 파일에 사용자 설정·공유 경로·시트 ID·인증 정보·서명 개인키를 넣지 않습니다.

## 개발과 검증

- Python 3.12 x64, requirements.txt로 의존성을 설치합니다.
- `python -m unittest discover -q`: 등록·중복 방지·OCR·압축·인증·업데이트·HWP 관련 검사.
- `python ui_smoke.py`: 기존 문서 선택·저장 위치·발신·OCR 대화창 검사.
- `python app.py --test-workflow`: 임시 로컬 파일과 모의 대장으로 실제 단계 화면·작업 스레드·첨부 묶기·별도 폴더 순번·실패 재시도·발신/직인 등록·이력·설정을 검사합니다. 실제 업무 시트나 공유폴더에 쓰지 않습니다.
- `python app.py --self-test`: UI·의존성·한국어 OCR·TLS 인증서 확인.
- CI는 공식 Python으로 PyInstaller 실행파일을 빌드하고 위 단계 화면 검사를 배포 실행파일로 다시 수행합니다. Ed25519 서명은 관리 PC에서만 하고 검증한 매니페스트로 공개 설치 ZIP을 게시합니다.
- OCR 런타임은 conda-forge Tesseract 5.5.1과 LGPL libarchive 3.8.11을 사용합니다. 공개 한국어 모델, 라이선스·빌드 정보·대응 소스를 함께 배포합니다. 공문 원본은 별도로 보관합니다.

## GitHub 배포 보관

새 설치 ZIP·실행파일·서명 매니페스트를 검증하고 정상 게시한 뒤 최신 공개 버전과 직전 정상 공개 버전 두 개를 남깁니다. 더 오래된 버전의 첨부 파일과 릴리스를 자동 삭제합니다. 실패한 새 배포나 정상 이전 버전이 없는 경우에는 정리하지 않습니다. 소스 커밋·브랜치·태그와 사용자 PC의 설정·이력·양식은 삭제하지 않습니다.

건축허가&사업계획승인은 시청공문·협의도면·시청회신, 사용승인&사용검사는 시청공문·협의도면·현장사진·시청회신을 기본 선택합니다. 저장 위치별로 항목을 선택·해제하며 선택된 순서대로 1부터 번호를 붙입니다. 여러 위치를 동시에 골라도 각 위치의 내부 구성을 따로 유지합니다. 수신 접수 완료 후 파일이 저장된 공문 폴더를 탐색기로 자동으로 열고, 완료 화면에 접수번호와 폴더 다시 열기 버튼을 표시합니다. 인쇄와 접수번호 수기 기재는 직접 합니다.

처리 이력에서 항목을 선택하고 **목록 삭제**를 누르면 해당 행이 이력 목록에서 사라집니다. Ctrl·Shift로 여러 항목을 선택하고 Ctrl+A로 전체 선택할 수 있습니다. 재실행 후에도 숨김을 유지합니다. 파일·Google 시트·접수/발신번호·직인 등록·중복 접수 방지용 기록은 유지하며, 발신할 수신 문서 목록에서도 계속 사용할 수 있습니다.

ZIP도 다른 문서처럼 감시 시작 이후 새로 저장된 파일만 자동 확인합니다. v2.7.0의 이전 ZIP 자동 확인과 ZIP 다시 확인 버튼은 제거했습니다. 이전 버전의 재개 기록에 빠진 옛 ZIP도 다시 불러오지 않습니다. 기존 ZIP이 필요하면 파일 추가로 직접 선택하세요. 이미 목록에 들어온 항목과 등록 이력은 임의로 삭제하지 않습니다.

수신·발신 저장 위치의 **폴더 추가 · 순서 변경**에서 내부 폴더 이름을 입력해 추가하고 위·아래 버튼으로 순서를 정합니다. 기본 폴더는 삭제하지 않으며 체크 해제할 수 있습니다. 추가한 폴더만 삭제할 수 있고, 체크한 항목만 최종 순서대로 1부터 연속 번호를 붙입니다. 추가 폴더가 많아도 기본 선택 줄은 유지하고 편집 창과 생성 예정 이름에서 확인합니다. 선택한 저장 위치별로 추가 폴더·체크·순서를 기억하며 뒤로가기와 저장 위치 변경에도 이어 씁니다. 기존에 저장을 시작한 문서의 구성 변경은 파일 취소 후 다시 저장할 때 적용합니다.

ZIP 안에 PDF·HWP/HWPX·HTML·DWG/DXF·워드·엑셀·PPT 등 문서·도면·오피스 파일이 있으면 첨부 묶음으로 표시합니다. 사진·기타 파일·일반 텍스트만 있는 ZIP은 자동 목록에서 제외합니다. 제목 확인에는 지원하는 문서만 표시하고, 접수 폴더에는 문서와 함께 원본 ZIP을 그대로 복사합니다. ZIP 내부의 다른 확장자·사진·메모 등은 원본 ZIP 안에 유지하므로 저장된 공문 폴더에서 직접 확인할 수 있습니다. 직접 ZIP을 추가하는 경우에도 같은 기준을 적용합니다.

제목이나 공통 붙임만 같다고 기존 공문으로 판단하지 않습니다. 새 접수는 본문·전체 첨부·원본 ZIP의 내용으로 구분하며 내용이 다르면 새 접수 대상으로 표시합니다. 같은 접수에서 오류·뒤로가기 후 재시도하는 경우에는 이미 진행한 등록과 번호를 유지합니다. 구버전에서 등록을 시도했던 거래는 기존 표식을 유지해 복구합니다. 공통 첨부를 재사용해도 다른 공문의 처리 기록을 덮어쓰지 않습니다. 여러 ZIP을 한 공문으로 직접 묶으면 원본 ZIP도 모두 함께 저장합니다.

수신 접수 후 발신을 이어 작성하면 이미 만든 센터발송 폴더를 기본 저장 위치로 사용합니다. 새 공문폴더나 내부폴더를 다시 만들지 않으며 양식을 바꾸어도 이 위치를 유지합니다. 다른 기존 폴더가 필요하면 저장 폴더 변경으로 직접 선택할 수 있습니다. 이미 저장된 HWP나 생성된 발신 폴더의 위치는 임의로 바꾸지 않습니다.
